Design notes (not part of the chart itself):
· Color is a sequential ramp in the app's warm "expense" hue (one hue, light→dark by magnitude) — day-of-week labels + a value tooltip + a legend give the magnitude a second, non-color reading, since color alone is never the only signal.
· Empty/no-spend days use the same neutral bg-white/5 treatment as empty states elsewhere in the app, not a 5th ramp step — "no data" and "lowest spend" read differently.
· Click opens the detail panel in place (no modal/navigation) and lists every transaction for that exact day — in the real build this reuses the existing GET /expenses?from=X&to=X&pageSize=100 endpoint (same one the Transactions table already calls), not a new endpoint — just a single-day filter.
· The heatmap's own daily totals come from the same GET /expenses/charts aggregation the other charts already use (days[]), so no new backend aggregation is needed either — this chart and "Expense trend → Day" read the identical series.
· "Last 12 months / Last 3 months" is a convenience toggle local to this chart — it doesn't affect the global date-range filter bar above the other charts.
· Becomes a real component (hand-rolled grid + Recharts-free, same as GitHub's own contribution graph — there's no standard Recharts primitive for this shape) once approved.
